Winterview is an interview-practice app I built for solo rehearsal. A user generates tailored prompts, answers them in a timed session, records each response, and reviews the result afterward.

I designed the product in Figma before implementing it. That design centered the product on one repeatable loop: prepare, answer, review, and return for another session.

## A complete practice flow

The core experience starts with question generation. Users provide the context for the kind of interview they want to practise, then receive a set of questions to work through.

The session needed to feel like practice rather than a static form. Winterview guides users through timed answers, saves recordings for delivery review, and keeps completed interviews available afterward.

The interview screen treats preparation and answering as separate phases. When one timer ends, the session moves to the next valid phase.

This simplified example shows the transition logic:

```ts
type Phase = "think" | "answer"

function nextPhase(phase: Phase, questionIndex: number, questionCount: number) {
  if (phase === "think") return "answer"
  return questionIndex + 1 < questionCount ? "think" : "complete"
}
```

The implementation starts and stops recording around the answer phase. Keeping those boundaries explicit made timeout and cleanup behavior easier to test.

## Connecting the browser pieces

I built Winterview as a solo project with a React and TypeScript frontend, an Express backend, Supabase for authentication and persistence, and Groq for question generation. Shared validation keeps the frontend and backend aligned, while the browser `MediaRecorder` API handles video capture.

This simplified excerpt shows the recording boundary:

```ts
const recorder = new MediaRecorder(stream, { mimeType: "video/webm" })
const chunks: Blob[] = []

recorder.ondataavailable = (event) => chunks.push(event.data)
recorder.onstop = () => saveClip(new Blob(chunks, { type: "video/webm" }))
recorder.start()
```

The browser provides the media stream. Winterview coordinates permissions, recording state, and saving the finished clip against its question.

## What I wanted to learn

Winterview gave me a practical way to use generated questions: the questions start the session, but the product's value comes from the timed practice and saved review.

Recording video in the browser introduced concrete concerns around permissions, media state, and session recovery. Keeping the flow small made those concerns easier to test.

## Result

Authenticated users can generate questions, complete timed recorded responses, review their answers, and return to saved interviews.

## Deployment

Winterview is live at [winterview.my.id](https://winterview.my.id), with the web app deployed on Vercel, the API on Render, and Supabase handling authentication, persistence, and recording storage. The source code is available on [GitHub](https://github.com/aryansfw/winterview).
