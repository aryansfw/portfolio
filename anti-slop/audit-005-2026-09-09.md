# Anti-Slop Audit 005

Date: 2026-09-09  
Scope: homepage, navigation, projects index, blog index, footer, and responsive shell  
Mode: after

## Findings

1. **MEDIUM - Homepage repeats three equal feature cards (R-05, R-14).** Beecloud, Winterview, and Sahabat CAPD use the same width, spacing, and internal structure, so nothing reads as the lead project. Make Beecloud the primary editorial feature and give the other two a smaller secondary composition.

2. **LOW - Screenshot frames waste useful space (R-20).** Landscape screenshots are limited by height inside very wide cards, producing large empty side areas at desktop widths. Let landscape screenshots fill their column and keep the height cap only for portrait captures.

3. **LOW - Projects page becomes one long repeated stack (R-05, R-20).** Five identical bordered blocks make scanning harder and weaken the studio-like direction. Use alternating image-and-text rows, with deliberate variation for portrait and landscape evidence.

4. **LOW - Inner-page hierarchy feels inherited from the starter (R-20).** Projects and Project notes use small `text-2xl` headings while the homepage uses a much stronger identity treatment. Increase inner-page titles, add a short intro measure, and use one consistent section divider.

5. **LOW - Navigation has little identity or location feedback (R-20, C-1).** Lowercase links alone look generic and the current page is not indicated. Add a compact name or monogram and a clear active-page state while keeping the navigation small.

6. **LOW - Writing index hides article relevance (R-05, C-3).** Date and title alone do not tell recruiters what each article demonstrates. Show the existing summary below each title and keep dates secondary.

7. **LOW - Theme follows the operating system but cannot be changed on-site (R-21).** Add a small working light/dark toggle with persisted preference, or document a strong reason for making the site system-only.

8. **HIGH - The document still enforces a 320px minimum width (R-03).** `html { min-width: 320px; }` guarantees horizontal overflow below that width. Remove the forced minimum and let content define its responsive limits.

## Recommended batch

Fix 1, 2, 3, 4, 5, 6, and 8 together. They form one coherent editorial redesign. Treat 7 as optional because it adds client-side state for limited portfolio value.

No UI changes were made during this audit.
