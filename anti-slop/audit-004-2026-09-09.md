# Portfolio design audit

Mode: after, retaining the user's previous selection. This report proposes changes; no application code was changed.

Direction: frontend portfolio for recruiters, bold studio-like presentation, ENERGY 3 / RHYTHM 3 / MOTION 1. Existing DESIGN.md also requires a centered reading column. A wider homepage and projects layout would revise that constraint while retaining centered alignment and narrow articles.

Evidence: current local source inspected in app/layout.tsx, app/page.tsx, app/components/projects.tsx, app/components/posts.tsx, app/components/nav.tsx, app/components/footer.tsx, app/global.css, and article layout. This is a source-based design review, not a browser visual or interaction certification. Prior build passes do not establish visual quality.

1. MEDIUM, R-14: All five projects receive the same homepage card presentation without a visible priority distinction. The shared component maps every project even under Featured projects. Select work intentionally: foreground Beecloud for production experience and Winterview for solo ownership, with Sahabat as another strong example; retain all five on Projects. Use larger image-led entries for selected work and compact entries for the remainder.

2. LOW, R-20/R-05: The global max-w-xl constrains homepage, project presentation, and articles to 576px despite different content needs. Propose a centered 960-1100px maximum for homepage and Projects, with articles around 640-680px. These are proposed sizes for browser testing, not measured optimal values. Preserve comfortable mobile padding.

3. LOW, R-20: Homepage hides project screenshots and outcomes behind the detailed flag, leaving titles, generic summaries, and technology pills as the primary evidence. Show a screenshot plus one concise contribution or verified outcome per selected project. Make technologies a secondary text line and connect projects with their existing articles.

4. LOW, R-20: Introduction repeats Frontend developer immediately after the heading, while displaying only Aryan. Set full name as the identity heading, role on a distinct line, and a concise introduction below. Bring Email and GitHub near that introduction; include Resume only once a PDF exists. Retain the existing accent and font unless browser review demonstrates a reason to change them.

5. LOW, R-05/R-20: Project details repeat Problem/Approach/Outcome blocks inside bordered cards, with images between the index and title. Put title and contribution before the screenshot, simplify surrounding borders, and give outcome a clear position. Preserve portrait screenshots without stretching. Sahabat's blog image lacks the mobile-screenshot class already used for Winterview, making its portrait scale inconsistent.

6. HIGH, R-03: html has min-width: 360px, which forces a document wider than a 320px viewport. Navigation links also use only py-1 and have no explicit 44px target. Remove the forced page minimum and establish adequate interactive hit areas. Verify narrow widths and keyboard focus in a browser before claiming a pass.

7. LOW, R-20: RSS receives a separate leading footer row while contact links sit below it. Group contact actions prominently and move RSS to a secondary position. Icons are optional and do not resolve this hierarchy problem.

Additional maintenance observation: app/sitemap.ts still declares https://aryanwardana.vercel.app, although the user supplied https://aryanshafawardana.vercel.app. Update the shared URL separately; it feeds metadata, sitemap, RSS, and robots.

Recommended sequence: 2, 4, 1 and 3 together, 5, 6, 7. Accessibility finding 6 should ship with any layout work. Keep motion at 1; these changes do not require animation or new dependencies.

Delivery status: audit complete. Implementation, browser layout checks, contrast measurements, theme checks, and interaction verification remain pending approval of findings.
